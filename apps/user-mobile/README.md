# user-mobile

The consumer-facing iOS app ("FynroX") — implementation of the 82 screens documented in [`../../docs/mobile/03-screen-inventory.md`](../../docs/mobile/03-screen-inventory.md). **Stack: React Native + Expo (decided 18 Aug 2026)** — see [`../../docs/platform/project-structure.md`](../../docs/platform/project-structure.md) §2.

This is the Phase 0/1/2/3/4 priority build per [`../../docs/platform/roadmap.md`](../../docs/platform/roadmap.md) — ships before the admin console and coach app. See [`../../docs/mobile/06-cross-app-integration.md`](../../docs/mobile/06-cross-app-integration.md) for how this app's data lines up with `api`, and [`../../docs/mobile/07-open-questions-gaps.md`](../../docs/mobile/07-open-questions-gaps.md) for open decisions — **including §9: this build uses email+password auth, not the Figma-specified phone+OTP flow**, pending an SMS-provider decision.

## What's actually built (Phase 0/1 done, Phase 2/3 done, Phase 4 started, Phase 5's Discovery & Booking slice added 25 Aug 2026)

- Navigation shell: Auth stack (Splash/Login/Signup) → **Onboarding wizard** (if incomplete) → 5-tab bottom nav (Today/Train/Fuel/Recover/More), matching [`../../docs/mobile/02-information-architecture.md`](../../docs/mobile/02-information-architecture.md) §1–2. `RootNavigator` branches on auth + onboarding state on every change — finishing the wizard drops straight into the tab shell with no extra navigation call.
- Auth wired end to end against `apps/api`: signup, login, silent token refresh on 401, logout — tokens stored in `expo-secure-store`, not plain storage.
- **5-step Setup wizard** (`src/screens/onboarding/`): About You (gender + age/weight/height steppers) → Goals (multi-select) → Training Level (4 experience cards) → Food/Diet (diet type + allergens) → Safety (medical conditions + injuries), matching [`../../docs/mobile/03-screen-inventory.md`](../../docs/mobile/03-screen-inventory.md) §A. Answers accumulate client-side (`OnboardingWizardContext`) and submit once, on the final step, to `PUT /users/me/onboarding`.

Today is a thin placeholder for its AI-brief/readiness-score elements (Phase 2), but got a real **Hydration** quick-add-a-glass card 19 Aug 2026 — see the Nutrition flow bullet below, gap §25 — plus, same day, a real **Continue Workout** card (only when an in-progress `WorkoutSession` was started today, deep-linking straight into Active Workout — this app's first cross-tab navigation, see `src/navigation/MainTabs.tsx`) and real **Quick Links** buttons that actually switch tabs — see gap §33 for why "today only" and for the pre-existing `WorkoutSessionStatus` "abandoned" gap this surfaced (half-closed 20 Aug 2026 by a real Abandon Workout button on Active Workout, see the Training flow bullet below). Recover remains a fully thin placeholder until the device-pairing backend lands (Phase 2).

## Setup

Requires `apps/api` running locally first (see its README).

```bash
npm install               # from the repo root (npm workspaces)
npm run typecheck --workspace=apps/user-mobile
npm run start --workspace=apps/user-mobile     # opens Expo dev tools — scan the QR with Expo Go, or press i/a for a simulator
```

> **Note on this scaffold:** this was built and typechecked/linted clean (`tsc --noEmit`, `eslint`) inside a headless cloud sandbox, which has no iOS Simulator or physical device to actually launch the app on — a real device/simulator run still needs to happen on your machine (or a real Expo/EAS build). **20 Aug 2026: this app has now genuinely been seen rendering, for the first time, inside this sandbox** — a `--platform web` export (see below) was served locally and screenshotted with the sandbox's pre-installed headless Chromium (Playwright), showing the real Welcome screen ("FynroX — Your Complete Wellness Operating System", Get Started/Sign In) and, after tapping "Sign In", the real Login screen (Email/Password fields, Log In, Create an account) — both pixel-correct against the design system tokens, with real React Navigation between them. **To be explicit: this is a dev-preview/verification aid, not a decision that this app now targets web as a real, supported platform** — `"web"` was added to `app.json`'s `platforms` array and `react-dom`/`react-native-web`/`@expo/metro-runtime` were installed purely to make that possible in an environment with no simulator; nothing about product scope or the iOS-first design changed. Getting there also required a real fix, not a web-only shim: `expo-secure-store` has no web implementation (its web target is an empty stub) and crashed the app at launch when the mobile client checked for a stored auth token — fixed with a new `src/lib/secureStore.ts` wrapper that's byte-for-byte identical to real `expo-secure-store` on iOS/native and only falls back to (explicitly non-secure) `localStorage` on web, solely so the preview build doesn't crash; see gap §37 for the full reasoning. **It does now genuinely Metro-bundle for iOS too**, separately — `npx expo export --platform ios` produces a real, complete production JS bundle (1084 modules, Hermes-compiled, zero errors) covering every screen built across this whole build. That didn't work out of the box: `expo/AppEntry.js` (the default Expo entry, which `main` pointed at) does a relative `import App from '../../App'` that assumes it's sitting in this app's own *local*, non-hoisted `node_modules/expo/` — but npm workspaces hoists `expo` up to the repo root's `node_modules`, so that relative path resolved to a nonexistent `App.tsx` at the monorepo root and bundling failed outright ("Unable to resolve module ../../App"). Fixed with the two changes any Expo-in-an-npm-workspaces-monorepo setup needs: a `metro.config.js` (Expo's own documented pattern — https://docs.expo.dev/guides/monorepos/) pointing Metro's `watchFolders`/`resolver.nodeModulesPaths` at both this app's node_modules and the hoisted root one, and a local `index.js` that calls `registerRootComponent(App)` itself (importing `./App` relative to itself, so it isn't affected by where `expo` is hoisted to) instead of relying on the broken `expo/AppEntry.js` — `package.json`'s `main` now points to `index.js`. This is a real, permanent monorepo-correctness fix, not a workaround specific to this sandbox — it would have been needed on any machine the moment someone actually tried to run this app for the first time. If `expo start` surfaces a dependency-version mismatch, run `npx expo install --check` to align versions with your installed Expo SDK. Separately, this same sandbox also can't reach Expo's own SDK-version-resolution API, so `npx expo install <package>` itself fails outright when adding a new Expo-managed dependency (hit four times now — `expo-notifications` for Reminders, `expo-clipboard` for Referral, `expo-local-authentication` for Biometric Unlock, then `expo-image-picker` for Progress Photos) — worked around every time by resolving the right version directly from npm's registry `dist-tags` instead; see `docs/mobile/07-open-questions-gaps.md` §21 for the reusable recipe. 20 Aug 2026 added a fifth dependency, `react-native-svg` for the weight-trend line chart, but it's not an Expo-published package so it has no `dist-tag` to read — its SDK-51-compatible version came straight from `node_modules/expo/bundledNativeModules.json` instead (the same file `expo install` reads from internally), see gap §36. This doesn't affect you on a normal machine — it's specific to this build environment's network allowlist, same category of limitation as `apps/api`'s `binaries.prisma.sh` block.
