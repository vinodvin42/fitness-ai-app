# Build Roadmap (proposed)

**31 Aug 2026 — remaining-gap closure batch.** A pass closing the last blocked slices across Phases 2–11, driven by four product decisions that were finally made (configurable per-coach commission; a 1-month subscription-credit referral reward; a manual-entry Recovery stopgap; coach-marketplace-first ordering). Shipped end-to-end (schema → API → apps), typecheck-consistent but **not yet run against a live DB** (this environment has none): **Coach Client Profile** + **Coach ↔ Client Messaging** (both apps' Messages/Clients tabs, previously "Coming soon"); **Coach Settlements** (10.06) with per-coach commission + a coach Earnings view; **Influencers** (07.01/02) + **Influencer Payouts** (10.07); **Business Analytics** (09.04); **Coupons** (06.05, incl. checkout redemption) + **Refunds** (06.04, real Razorpay refund path); **Referral rewards** (§O, 1-month credit granted on a referee's paid conversion); **Payment Success/Failed screens** + a **feature-comparison table** (§M); and the **Recovery manual-entry log** (§E). New Prisma models (CoachMessage, CoachSettlement, Influencer, InfluencerPayout, Coupon, CouponRedemption, Refund, ReferralReward, RecoveryLog) mean a `db:migrate` is required before this runs. See each `apps/api` module's own doc comment for the real-vs-honest-boundary reasoning. The per-phase entries below predate this batch and were not all rewritten — the code doc-comments are the source of truth.

**20 Aug 2026:** see [`mvp-launch-plan.md`](mvp-launch-plan.md) for the delivery plan that turns Phases 0–4 below into an actual launch — current state, the specific decisions blocking remaining work, infra/ops needs, and sequenced milestones to ship.

**Priority decision (18 Aug 2026):** the consumer mobile app (`docs/mobile/`, `v1-user`, 82 screens) ships **first**, ahead of the admin console and the coach app. This supersedes the admin-console-first ordering this roadmap used previously. The phases below are sequenced by (a) dependency — auth, backend, and a minimal content path block everything else — and (b) what the mobile app actually needs to be usable and monetizable on its own, before assuming any admin tooling or live coaches exist. Each phase assumes the gaps relevant to it (see the `07-open-questions-gaps.md` in each app's folder) have been resolved first.
